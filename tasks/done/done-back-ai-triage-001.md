## Objectif

Endpoint de triage AI qui analyse les symptomes decrits en texte libre et suggere severite, duree, specialite.

## Spec de reference

`docs/AI-FEATURES-SPEC.md` section 3 (Feature 1 — AI Triage veterinaire)

## Implementation

### Command + Handler

- `TriageSymptomsCommand(Symptoms, Species, Breed?, AgeMonths?, WeightKg?)`
- `TriageSymptomsHandler` : valide → construit prompt → appelle IChatClient → parse JSON → persiste → retourne Result<TriageSuggestionDto>
- `TriageSymptomsValidator` : Symptoms requis, Species requis

### Endpoint

`POST /api/ai/triage` (roles: Vet, Receptionist, Admin, rate limit: policy "api")

### Response

```json
{
  "severity": "Normal",
  "estimatedDurationMinutes": 30,
  "recommendedSpecialty": "generaliste",
  "reasoning": "...",
  "disclaimer": "This suggestion is generated by AI for informational purposes only...",
  "confidence": 0.82,
  "triageId": "uuid"
}
```

### Regles metier (PO)

- **Langue EN par defaut** (pas FR — marche UAE). Disclaimer en EN et AR selon la langue de l'interface.
- Disclaimer constant, jamais genere par le LLM
- Temperature 0.1 (reponses deterministes)
- Classification en 3 niveaux : Emergency / Normal / Routine
- Interdiction de recommander des medicaments
- Interdiction de poser un diagnostic

### Persistance (audit)

Entite `TriageResult` dans AIDbContext, table `ai.triage_results` :
- Id, ClinicId, Symptoms, Species, Breed, AgeMonths, WeightKg
- SuggestedSeverity, EstimatedDuration, RecommendedSpecialty, Reasoning, Confidence
- WasAccepted, OverriddenSeverity, ModelUsed, PromptTokens, CompletionTokens, LatencyMs
- CreatedAt, CreatedBy

### Gestion erreurs

- `AI_SERVICE_UNAVAILABLE` — LLM indisponible
- `AI_RESPONSE_INVALID` — reponse non parsable
